# /skill:board — пульт запуска

> **ЯЗЫК / LANGUAGE:** Пользователь общается на русском. Все ответы пользователю и артефакты пиши на русском. Стремись рассуждать на русском, но если reasoning уходит на английский — это не ошибка; главное, чтобы финальные ответы и артефакты были на русском. Код, команды, идентификаторы, пути и технические термины оставляй в оригинале.

Пульт — `ai-launcher/BOARD.md`. Он **витрина** открытых GitHub Issues на
`AutonomaCo/promelectron`, а не отдельный список. Расхождение между ними — всегда ошибка
борда, а не бэклога.

> ## 📖 Правила живут не здесь
> Форма пульта, замки и порядок сверки — **[`ai-launcher/CONVENTIONS.md`](../../../ai-launcher/CONVENTIONS.md)**.
> Прочитай его прежде чем править борд. Это общий документ с Claude-двойником `/board`:
> борд у команды один, и дублировать правила в двух наборах скиллов значит гарантированно
> их разъехать. Здесь — только сценарий команды.

## Без аргумента: показать

1. Прочитай `ai-launcher/BOARD.md`.
2. Ответь коротко и по делу: что можно брать прямо сейчас (🟢 со свободным замком), что ждёт
   ответа владельца, что в работе и какие замки заняты, **что из «⏰ Ждут условия» уже можно
   проверить**.
3. **Условия из «⏰ Ждут условия» проверь сам — это дёшево.** Они написаны проверяемыми:
   состояние ветки, открытый PR, ответ ручки, доступность внешнего сервиса. Наступило — скажи
   об этом **первым делом**, до всего остального. Не наступило — одной строкой.

   Хвост из этого раздела теряется незаметнее прочих: PR смержен, борд зелёный, пункт выглядит
   готовым — а проверка, ради которой всё делалось, не проведена.
4. Не пересказывай борд целиком. Выжимка и ссылки на якоря.

Показ — операция только на чтение, ничего не правь.

## `refresh`: сверить с реальностью и переписать

Борд врёт легко и незаметно: сессия умерла, ветка смёржена, замок остался занят. Сверяй
**фактами**. Полный порядок — раздел 5 `CONVENTIONS.md`. Кратко:

```bash
git worktree list
git branch -a --sort=-committerdate | head -20
gh pr list --repo AutonomaCo/promelectron --state open --limit 20
gh issue list --repo AutonomaCo/promelectron --state open --limit 100 \
  --json number,title,labels,url
git log --oneline -10
```

Кластер, если пункт про инфраструктуру:
`KUBECONFIG=~/.kube/AutonomaCo kubectl -n promelectron-test get deploy,pods`.

1. «🔵 В работе»: ветка жива? PR открыт или смёржен? Смёржен — закрой issue **с доказательством**
   (номер PR, SHA), убери с борда, освободи замок.
2. «⏰ Ждут условия» сверяй тоже, включая правило «смержено ≠ проверено».
3. Пересчитай «Замки заняты / Свободны» — самое частое расхождение.
4. Синхронизируй с бэклогом в обе стороны: пункта нет в открытых Issues — убрать и сказать
   владельцу; открытый issue не на борде — добавить (без кнопки, если промпта нет).
5. Обнови шапку: SHA `main` и дату.
6. Прогони `python3 scripts/check-board.py`. Красный — чини до коммита: борд правится прямым
   push'ем в `main`, ревью на нём нет.

Колонки доски GitHub Project требуют scope `read:project`. `gh project …` ответил
`missing required scopes` — **скажи об этом вслух**, попроси владельца выполнить у себя
`gh auth refresh -s project`, а сверку доведи по `gh issue list` + веткам и PR.

## Правила

- **Борд — пульт, а не журнал.** Разборы и история живут в issue, `docs/decisions/log.md`,
  `docs/journal/session-log.md` и `git log`.
- **Кнопка только там, где есть промпт** в `ai-launcher/prompts/`. Нет промпта — пункт в списке
  «заведено, но кнопки нет».
- **Кнопка пишется как `make ai PROMPT=…`** — она нейтральна к агенту. Не подставляй `kimi …`
  напрямую: у владельца та же кнопка запускает claude через его `Makefile.override.mk`.
- **🟢 только при реально свободном замке.** Два пункта с одним замком не бывают 🟢 одновременно.
- **Не заводи issue сам без спроса.** Локальный пункт без issue показывается отдельным списком,
  а заводить решает владелец.
