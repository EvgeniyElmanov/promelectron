# Agent Commons для workflow-навыков Promelectron

Общие правила для всех workflow-навыков (`implement`, `fix`, `review`, `deploy`, `context-sync`, `plan-maintainer`).
Загружай эту reference в субагентах при необходимости вместо дублирования полного текста в каждом `SKILL.md`.

---

## Language Rule / Языковое правило

> **Это единый источник истины о языке.** Все прочие скиллы, правила и `AGENTS.md`
> ссылаются сюда и не дублируют формулировку.

Когда пользователь пишет по-русски:

- **Финальные ответы, отчёты и артефакты — на русском.** Это относится к ответам
  пользователю и родительскому агенту, а также к содержимому `task.md`, `spec.md`,
  `findings.md`, `test-findings.md`, `SESSION_LOG.md`, комментариям к PR и сообщениям.
- **Внутреннее рассуждение (thinking).** Модель Kimi K3 работает с
  принудительным thinking mode, и язык внутреннего рассуждения промптом надёжно не
  управляется. Стремись рассуждать по-русски, но сбой языка *thinking* не считается
  ошибкой выполнения — критичен язык итоговых ответов и артефактов.
- **Как реально усилить русский в рассуждении:** формулируй ключевые части задания
  (роль, задача, критерии проверки) по-русски или билингвально с русским впереди.
  Одна английская строка-«заклинание» в англоязычном контексте не работает.
- **Код, команды, идентификаторы, пути к файлам и технические термины** всегда
  оставляй в оригинальном виде.

### Full subagent prompt block / Преамбула для субагентов

Запуская субагента при русскоязычном пользователе, добавь эту директиву в **начало
и в конец** его промпта (единая формулировка, не изобретай свою):

> ЯЗЫК / LANGUAGE: Пользователь общается на русском. Ключевые инструкции этой задачи — на русском. Отвечай родительскому агенту и пиши все артефакты (spec, findings, отчёты, SESSION_LOG) на русском. Стремись рассуждать на русском, но если reasoning уходит на английский — это не ошибка; главное, чтобы финальные ответы и артефакты были на русском. При multi-step tool calling обязательно сохраняй `reasoning_content` из ассистентских сообщений в истории. Код, команды, идентификаторы, пути и технические термины оставляй в оригинале.

Workflow-навыки не должны дублировать этот блок. Вместо этого в промпте субагента
укажите: *"Предварь этот промпт комбинированной преамбулой из Rule: Agent Commons
(раздел Full subagent prompt block)."* Родительский агент отвечает за вставку блока.

```text
ЯЗЫК / LANGUAGE: Пользователь общается на русском. Ключевые инструкции этой задачи — на русском. Отвечай родительскому агенту и пиши все артефакты (spec, findings, отчёты, SESSION_LOG) на русском. Стремись рассуждать на русском, но если reasoning уходит на английский — это не ошибка; главное, чтобы финальные ответы и артефакты были на русском. При multi-step tool calling обязательно сохраняй `reasoning_content` из ассистентских сообщений в истории. Код, команды, идентификаторы, пути и технические термины оставляй в оригинале.

Important: Kimi K3 always has thinking mode enabled (it cannot be disabled; configure `reasoning_effort`: `low` / `high` / `max`, default `max`), with fixed `temperature=1.0`, `top_p=0.95`, `n=1`, `presence_penalty=0.0`, `frequency_penalty=0.0`. In multi-turn conversations and tool calls, return the complete assistant message unchanged.
```

## Политика повторных попыток (Retry Policy)

При использовании `Agent` или `AgentSwarm`:

- Повторять до 4 попыток (3 повторных) при временных ошибках (502, 504, timeout).
- Использовать экспоненциальную задержку: 2s, 4s, 8s.
- Сохранять `reasoning_content` между multi-turn tool calls.
- Остановиться и сообщить пользователю, если все попытки неудачны.

> **Уровни retry (Kimi Code CLI ≥ v0.25):** CLI сам повторяет временно неудачные LLM-запросы — per-step retry limit вырос с 3 до 10. Политика выше (4 попытки) относится к **субагентному уровню** — перезапуску целого субагента, а не отдельного LLM-шага; не увеличивай её, опираясь на дефолт CLI: 4 попыток достаточно, т.к. транзиентные сбои шагов уже покрыты рантаймом.

## Правило одиночного прогона тестов (Single Test Run Rule)

**В одном Docker-PG одновременно выполняется только один `make test-backend`.**

Тестовый хелпер backend создаёт per-worker БД из общего template database и дропает его при teardown. Два параллельных прогона (например, фоновый прогон субагента + прогон оркестратора/QA) дают гонку: второй прогон падает пачкой `InvalidCatalogNameError: template database "promelectron_test_template" does not exist` — это НЕ регрессия кода (см. `.kimi-code/LESSONS_LEARNED.md`, 2026-08-01: 417 ложных errors при зелёном коде).

Обязательно для всех ролей (developer, qa, e2e-tester, reviewer) и оркестратора:

- Запускай `make test-backend` только в **foreground** и дожидайся результата.
- **NEVER** оставляй фоновый прогон тестов после своего отчёта; если запустил в фоне — останови или дождись завершения.
- Оркестратор перед собственным прогоном проверяет отсутствие живых pytest (`ps aux | grep pytest`) и дожидается/останавливает фоновые прогоны субагентов.
- Диагноз «это гонка, а не код»: массовый `InvalidCatalogNameError ... template ... does not exist` → проверь параллельные pytest и перезапусти одиночный прогон.

## Ограничения модели и API (Kimi K3)

Pipeline ориентирован на модель **Kimi K3** (2.8T, контекстное окно 1M токенов).
Thinking mode **всегда включён** и отключить его нельзя; глубина рассуждения задаётся
полем `reasoning_effort` (`low` / `high` / `max`, по умолчанию `max`). Старый параметр
K2.x `thinking={"type":"enabled"}` больше не используется. Фиксированные параметры API
(любое другое значение вызовет ошибку): `temperature=1.0`, `top_p=0.95`, `n=1`,
`presence_penalty=0.0`, `frequency_penalty=0.0`. `max_completion_tokens` по умолчанию
131072, максимум 1048576. В multi-turn диалогах и tool calls **необходимо** возвращать
полное assistant message без изменений (включая `reasoning_content`). Контекстное
кэширование префиксов автоматическое (cache hit при >256 токенах неизменного префикса):
держи стабильное начало промптов субагентов, переменный контент — в конец.

## Проверка размера контекста (Kimi K3)

Перед запуском субагентов оцени размер контекста задачи:

```bash
python scripts/implement-pipeline.py check-context <task-id>
```

- Если `ESTIMATED_TOKENS` >= 600000, читай `.agent/runs/<task-id>/CONTEXT_SUMMARY.md` вместо полной истории.
- Логируй оценочное количество токенов в `.agent/SESSION_LOG.md`.

### SESSION_LOG — только хвост

Субагенты читают `.agent/SESSION_LOG.md` только как tail (~200 строк, `Read` с `line_offset: -200` или `tail -200`); читать файл целиком запрещено. История старше хвоста живёт в `.agent/SESSION_LOG.archive.md` и читается только при явной необходимости.

Kimi K3 имеет контекстное окно 1M с обязательным thinking mode. Порог предупреждения 600K (~60% окна) оставляет ~400K для system prompt, reasoning_content, выводов инструментов и генерации ответа.
