# Promelectron — общий индекс для AI-агентов

Интернет-магазин электротоваров: FastAPI + Vue 3 + PostgreSQL + Redis + Kubernetes.
Тестовый контур — https://promelectron-test.aidrivencode.ru

Репозиторий ведут **несколько агентов одновременно**: Claude Code, Kimi Code, дальше Gemini.
Этот файл — то, что читают все трое. Инструменто-специфичное живёт отдельно и ссылается сюда:

| Агент | Точка входа | Инструменто-специфичное |
|---|---|---|
| Claude Code | `CLAUDE.md` (импортирует этот файл) | `.claude/skills/` — скиллы и слэш-команды, `.claude/rules/` — правила по `paths:`, `.claude/agents/` — субагенты |
| Kimi Code | `.kimi-code/AGENTS.md` | `.kimi-code/skills/` — ролевые и workflow-навыки, `.kimi-code/rules/` — конвенции, `.kimi-code/BUNDLE.md` — реестр |
| Gemini | — (подключится позже) | — |

**Правило дублирования:** суть — в общем файле, у инструмента — тонкая обёртка со ссылкой.
Два набора скиллов с одинаковой логикой гарантированно разъедутся; три — тем более.

## Обязательный контекст сессии

1. `PROJECT_CONTEXT.md` — стек, статус фич, инвентарь API
2. `ai-launcher/BOARD.md` — **пульт запуска**: что брать сейчас, какие замки заняты, что ждёт условия
3. `.agent/BLOCKERS.md` — активные блокеры
4. `.agent/BACKLOG.md` — указатель на бэклог и на то, что ещё не заведено

Дальше — по теме задачи, не раньше.

## Замки: как разводится параллельная работа

Замок — область файлов. **Два пункта с одним замком параллельно не идут.**

`backend` · `frontend` · `e2e` · `infra` · `docs` · `harness` · `none` · `all`

Пункт берёт **все** замки, чьи файлы трогает. Замок занимается на пульте **до** создания
worktree. Занят другим — остановись и скажи владельцу, а не «аккуратно рядом».
Метка зоны на issue = её замок. Таблица покрытия — `ai-launcher/CONVENTIONS.md` §2.

## Запуск задачи

Кнопка на пульте одна для всех агентов:

```bash
make ai PROMPT=ai-launcher/prompts/<замок>_<issue#>-<слаг>.prompt.txt
```

Чем она запускается — claude, kimi или следующий — задаётся машинно-локально в
`Makefile.override.mk` (в `.gitignore`; образец — `ai-launcher/README.md`).
`make ai-check` проверяет настройку.

**Issue пишется человеку, промпт — агенту.** Тело issue: проблема, почему важно, проверяемое
«готово, когда». Инструкции агенту — в `ai-launcher/prompts/`, подключаются блоком «Запуск».
Почему разделено и как связывается — `ai-launcher/CONVENTIONS.md` §7.

## Жёсткие правила

- **NEVER** создавать модель БД без миграции; `make migrate-check` должен быть зелёным.
- **NEVER** писать эндпоинт без тестов.
- **NEVER** коммитить без явного одобрения владельца.
- **NEVER** менять существующие пути эндпоинтов без отдельной задачи — от них зависит фронтенд.
- **NEVER** трогать `.github/` и `infra/helm/` без явного разрешения.
- **NEVER** коммитить секреты — только через SOPS или GitHub Secrets.
- **NEVER** заводить дублирующий issue для той же задачи.
- **ALWAYS** прогонять тесты до отчёта о завершении.
- **ALWAYS** привязывать GitHub Issue до начала разработки.
- **ALWAYS** двигать issue по фазам: взял → `in-progress`, PR → `in-review`, смержил → закрыт
  **с доказательством** (номер PR, SHA, вывод прогона). Порядок — `ai-launcher/CONVENTIONS.md` §8.
- **ALWAYS** обновлять пульт после работы: снять закрытый пункт, освободить замок.
  Не обновили — коллега на другом агенте возьмёт занятое.

## Язык

Владелец общается по-русски. Ответы, отчёты, тела issue, заголовки и описания PR — по-русски.
Код, команды, идентификаторы, пути и технические термины — в оригинале.
Делегируя субагенту, скажи ему это явно.

## После работы

1. `.agent/SESSION_LOG.md` — что сделано, с доказательствами.
2. `ai-launcher/BOARD.md` — снять пункт, освободить замок, пересчитать блок «Замки».
3. `.agent/DECISIONS.md` — если принято решение, которое кто-то потом переспросит.
4. `.agent/BLOCKERS.md` — если появился блокер.
5. `PROJECT_CONTEXT.md` — если изменилась архитектура.
