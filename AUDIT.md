## 4. Топ-8 критических gaps

### 🔴 P0 — Блокируют запуск или выручку

| # | Проблема | Почему критично | Где в коде | Оценка |
|---|---------|----------------|-----------|--------|
| 1 | **Mock-оплата** | Без реального эквайринга невозможно принимать деньги | `services/payment_service.py` | 2-3 недели |
| 2 | **Гостевая корзина** | 60-70% пользователей бросают корзину, если требуется регистрация | `api/cart.py`, `models/cart.py` | 1-2 недели |
| 3 | **Отсутствие мониторинга** | Падения в production не заметны до жалоб пользователей | Весь проект | 1 неделя |
| 4 | **Автозапуск Alembic в lifespan** | Race condition при старте нескольких реплик, возможен deadlock | `main.py:43-49` | 2 дня |
| 5 | **Hardcoded secrets** | SECRET_KEY default, SEED_SECRET, seed passwords — production security risk | `core/config.py`, `api/seed.py`, `seed_data.py` | 2-3 дня |

### 🟡 P1 — Блокируют рост

| # | Проблема | Почему важно | Где в коде | Оценка |
|---|---------|-------------|-----------|--------|
| 6 | **Нет реальной логистики** | Нет интеграции СДЭК/Почта, нет расчёта стоимости, нет трекинга | `models/order.py` (tracking_number текст) | 3-4 недели |
| 7 | **Нет промо-системы** | Невозможно запускать акции, скидки, программы лояльности | Отсутствует | 2-3 недели |
| 8 | **Product.price = Float** | Денежные расчёты с плавающей точкой = ошибки округления | `models/product.py` | 2-3 дня |

## 5. Технический долг

### Backend

| Проблема | Локация | Серьёзность | Почему болит |
|---------|---------|------------|-------------|
| **God service OrderService** | `services/order_service.py` (420 строк) | 🔴 Высокая | Смешана логика создания, статусов, админ-апдейтов, side-effects (email/notification) |
| **Дублирование supplier lookup** | `api/orders.py` (3×), `api/products.py` (3×), `api/analytics.py` | 🟡 Средняя | 7 копий одного и того же блока кода |
| **Нет repository layer** | `services/*.py` | 🟡 Средняя | Сервисы напрямую используют SQLAlchemy queries — сложно тестировать и менять БД |
| **Side-effects в request thread** | `services/order_service.py`, `services/payment_service.py` | 🟡 Средняя | Email/notification отправляются синхронно, блокируя ответ |
| **Нет middleware package** | `main.py` | 🟢 Низкая | CORS, rate limit, exception handlers живут в main.py |
| **Нет доменных событий** | — | 🟡 Средняя | Order/Payment напрямую зависят от Email/Notification/WS |
| **JWT в localStorage** | `frontend/src/services/api.js` | 🟡 Средняя | Уязвимость к XSS, предпочтительны HttpOnly cookies |
| **In-memory rate limiting** | `utils/rate_limiter.py` | 🟡 Средняя | В K8s с несколькими репликами лимиты не работают |
| **Numeric vs Float** | `models/product.py` vs `models/order.py` | 🟡 Средняя | Несогласованность типов для денег |
| **OAuth без state** | `api/auth.py` | 🟡 Средняя | Уязвимость к CSRF |
| **No ON DELETE constraints** | Модели | 🟢 Низкая | Полагаемся на ORM cascade |

## 8. Рекомендации по рефакторингу

### Что доработать (не переписывать)

| Компонент | Почему достаточно доработки |
|-----------|---------------------------|
| FastAPI + SQLAlchemy | Прочная async-основа, SQLAlchemy 2.0 — современный стандарт |
| Vue 3 + Vite | Актуальный стек, нет причин менять |
| PostgreSQL | Можно добавить tsvector для search, не менять на Mongo |
| Redis | Хорош для кэша, rate limit, sessions. Не нужен Kafka на текущем этапе |
| MinIO | Работает, при росте — миграция на S3-compatible без кода |

### Что стоит переделать

| Компонент | Почему |
|-----------|--------|
| `OrderService` (420 строк) | Разбить на `OrderLifecycleService`, `SupplierOrderService`, `OrderSideEffectHandler` |
| `Admin.vue` (1317 строк) | Разбить на отдельные view-компоненты по табам |
| State management (frontend) | Перейти с ad-hoc composables на Pinia |
| Rate limiting | Перейти с in-memory на Redis-backed |
| Email/Notification side-effects | Вынести в Celery tasks через event bus |

## 9. Оценка ресурсов

### Фаза 1 (1-2 мес): 2 backend + 1 frontend + 1 devops
- Backend: платежи, гостевая корзина, security fixes
- Frontend: гостевая корзина (UI), Pinia foundation
- DevOps: мониторинг, Helm фиксы, backup

### Фаза 2 (2-4 мес): 2 backend + 2 frontend + 1 devops
- Backend: доставка, промо, search, возвраты
- Frontend: Pinia полный переход, lazy loading, промо UI, доставка UI
- DevOps: CDN, HPA, staging environment

### Фаза 3 (4-8 мес): 3 backend + 2 frontend + 1 devops + 1 mobile + 1 ML
- Backend: микросервисы, event sourcing, ML интеграция
- Frontend: SSR, A/B тесты, i18n
- DevOps: multi-region, advanced monitoring
- Mobile: React Native / Flutter MVP
- ML: рекомендации, поисковый ранкинг

## 10. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Legacy код усложняет развитие заказов (возвраты, логистика) | Высокая | Высокое | Выделить 1 спринт на рефактор OrderService перед новыми фичами заказов |
| Интеграция платежей затягивается | Средняя | Высокое | Начать с ЮKassa (самая простая интеграция в РФ) |
| Рост без мониторинга = аварии | Высокая | Высокое | P0: Sentry + Prometheus в первый спринт |
| Нагрузка на PostgreSQL | Средняя | Среднее | P1: read replicas, connection pool tuning |
| Frontend bundle size | Средняя | Среднее | P1: lazy loading, code splitting |
