## Задача

После #211 сервер сверяет цену доставки с расчётом СДЭК: расхождение → 409 «Стоимость
доставки устарела», недоступность СДЭК → 503 (fail-closed). Фронт на это лишь показывает
текст `detail` в toast: заказ не создан, цена не обновлена, повторный сабмит даёт тот же
409 — тупик на денежном пути. Подробности — `gh issue view 269`.

Решение СОГЛАСОВАНО с владельцем (2026-09-29): #269 делаем как ядро обработки (пересчёт
на создании заказа); #270 (полная обработка 409/503: retry, тосты на 422) НЕ закрывать
дублём — после мержа прокомментировать в #270, какой остаток остался.

## Что уже известно

- Два пути оформления с одинаковой болезнью: авторизованный `frontend/src/views/Cart.vue`
  (~строка 656) и гостевой `frontend/src/views/GuestCheckout.vue` (~строка 273) — оба на
  4xx/5xx от создания заказа просто тостят `detail`.
- Эндпоинты: `POST /orders/create/` и `POST /orders/create-guest/` (со trailing slash!),
  пересчёт тарифа — `POST /cdek/calculate/`. Пути НЕ менять (жёсткое правило репо).
- Ответы сервера (#211): 409 `{"detail": "Стоимость доставки устарела. …"}`; 503 при
  недоступности СДЭК; 422 на схемных ошибках (цена < 0 и т.п.).
- e2e-мок виджета СДЭК (из #211) берёт ПВЗ и цену из реального `/cdek/calculate/` —
  переиспользуй его для сценария «409 один раз → пересчёт → успех».
- Логика выбора доставки (ПВЗ, тариф, цена) уже живёт в обеих view; дублировать её
  не надо — вынеси обработку 409/503 в общий composable/хелпер, чтобы пути не разъехались
  (критерий issue: одинаковое поведение).

## Порядок

1. Общий обработчик ответа создания заказа (composable, например
   `useOrderSubmission`/`useDeliveryRecalc` — по неймингу соседних composables):
   409 → `POST /cdek/calculate/` → обновить выбранную доставку новой ценой → понятное
   сообщение пользователю со старой и новой ценой → кнопка/подтверждение «Оформить по
   новой цене» (авто-retry без подтверждения НЕ делать — цена выросла, это деньги).
   503 → «Сервис доставки временно недоступен, попробуйте позже» + возможность повторить.
2. Подключить обработчик в `Cart.vue` и `GuestCheckout.vue` вместо голого toast.
3. Тесты: vitest на обработчик (409 → пересчёт вызван, цена обновлена, сообщение показано;
   503 → дружелюбное сообщение; успех без 409 — поведение не изменилось); e2e-кейс
   «409 → пересчёт → успешный заказ» на моке из #211 (критерий issue).
4. После мержа PR: комментарий в #270 — что из объёма 270 закрыто этим PR, что осталось
   (retry-стратегии, 422-тосты).
