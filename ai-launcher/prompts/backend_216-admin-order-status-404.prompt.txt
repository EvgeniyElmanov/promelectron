## Задача

`PUT /admin/orders/{order_id}/status/` закрыт `Depends(get_current_active_admin)`,
но сервис ищет заказ с фильтром `Order.user_id == current_user.id` — админ находит только
свои собственные заказы, на любом заказе покупателя ручка возвращает 404. Вместе с ней
мертва вся машина переходов `_validate_status_transition`. Подробности — `gh issue view 216`.

Места:
- `backend/src/app/services/order_service.py:942` — фильтр по `user_id` в админском пути;
- `backend/src/app/api/orders.py:238-244` — эндпоинт;
- корректный образец рядом: `cancel_order_by_admin` (`order_service.py:731`) — там проверка
  владения для админа устроена правильно.

Тестов на эту ручку нет вовсе: `grep "status/" backend/tests/test_orders.py` — пусто.
Это и есть причина, по которой поломка дожила до сегодня незамеченной.

## Порядок

1. Сначала воспроизведи: тест «админ меняет статус чужого заказа» — обязан падать с 404
   до фикса.
2. Убери фильтр `user_id` из админского пути смены статуса (по образцу
   `cancel_order_by_admin`). Пользовательский путь НЕ трогать: проверка владения для
   обычного пользователя должна остаться.
3. Покрой тестами по «Готово, когда» из issue: админ меняет чужой заказ — успех;
   обычный пользователь на чужом заказе — 404; недопустимый переход статуса — 400.
4. Проверь, нет ли того же фильтра в других админских ручках заказов — если найдёшь,
   НЕ чини здесь: заведи отдельный issue и скажи владельцу.
