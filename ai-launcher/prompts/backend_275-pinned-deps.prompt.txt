## Задача

Зависимости backend без пинов → сборка Docker-образа невоспроизводима: каждая пересборка
тянет свежие версии (инцидент 2026-09-28 — SQLAlchemy 2.1.1 убил deploy-test без изменений
кода; прецедент раньше — ruff 0.16.1 против 0.15.13). Подробности — `gh issue view 275`.

Решение СОГЛАСОВАНО с владельцем (2026-09-29): **вариант A** — lock через
`uv pip compile`, БЕЗ переезда на проектный режим uv (pyproject `[project]` + `uv sync`
— это вариант B, отдельная задача, здесь не делать).

## Что уже известно

- `backend/requirements.txt` (~20 пакетов): пины только у `fastapi==0.104.1` и
  `meilisearch==0.42.0`, остальное без версий. `requirements-dev.txt` =
  `-r requirements.txt` + pytest/ruff (ruff уже запинен `==0.15.13` после инцидента).
- `backend/Dockerfile`: `python:3.12-slim`, ставит `pip install --no-cache-dir -r
  requirements-dev.txt`. Тесты (`make test-backend`) бегут в этом же образе через
  compose-сервис `api` — залочив образ, закрываем и CI, и тесты.
- `backend/pyproject.toml` содержит ТОЛЬКО `[tool.pytest.ini_options]` — не трогать
  его под `[project]`, это вариант B.
- `backend/uv.lock` — ПУСТАЯ заглушка (3 строки, ноль пакетов, `requires-python >=3.13`
  — неверно, в образе 3.12). Не коммичена. Удалить, на неё не опираться.
- `uv` установлен локально (0.11.13). Python проекта — 3.12 (как в образе).
- Локальный venv (корневой `venv/`) ставится из requirements-dev — после переезда
  должен ставиться из lock, иначе «локально работает, в образе падает» останется.

## Порядок

1. Зафиксировать ТЕКУЩЕЕ дерево версий, а не свежие: собрать образ как есть,
   `pip freeze` из контейнера → constraints для первого compile. Массовый апгрейд
   версий — НЕ входит в задачу (осознанное обновление — отдельным действием потом).
   Если по ходу выяснится, что текущее дерево не резолвится/конфликтует — зафиксируй
   расхождение в spec и реши с владельцем до правок.
2. Сгенерировать lock-файлы под Python 3.12:
   `uv pip compile requirements.txt -o requirements.lock --python-version 3.12`
   `uv pip compile requirements-dev.txt -o requirements-dev.lock --python-version 3.12`
   (constraints из п.1; заголовок-генералка uv с командой пересборки сохранить).
3. Dockerfile: ставить из `requirements-dev.lock` (тот же pip, минимальный diff;
   `uv pip install --system` в образе — допустимо, но не обязательно).
4. Makefile: цели `deps-lock` (пересборка lock по constraints) и `deps-upgrade`
   (`uv pip compile --upgrade`) — обновление версий становится видимым diff в git.
5. Локальный venv: документированная установка из lock (README/docs разработчика).
6. Доказательство воспроизводимости (критерий issue): ДВЕ пересборки образа из одного
   коммита → идентичный `pip freeze`; вывод приложить в PR. Плюс `make test-backend`
   зелёный на собранном по-новому образе.
