## Задача

Rate limit в кластере: uvicorn стартует с `--proxy-headers --forwarded-allow-ips='*'`
(`backend/docker-entrypoint.sh`), то есть доверяет X-Forwarded-For от кого угодно.
nginx-ingress дописывает клиентский XFF, а не затирает — при доверии `'*'` ключом лимита
становится подсунутый клиентом адрес: вращая XFF, лимиты обходятся полностью. Плюс гостевой
эндпоинт заказа вообще без лимита (перебор order_id → чужие адреса/телефоны). Подробности —
`gh issue view 220` (тело переформулировано 2026-10-06: старая гипотеза «лимиты по IP
ingress-пода» не доказана — `--proxy-headers` стоит с 20.05.2026, коммит 6f60cff).

Объём СОГЛАСОВАН с владельцем (2026-10-06): верификация → закрутка forwarded-allow-ips →
лимит на гостевой эндпоинт → тесты → подчистить устаревший комментарий.

## Порядок

1. **Верификация на живом test** (KUBECONFIG=~/.kube/AutonomaCo, namespace promelectron-test):
   повторные запросы к лимитированному эндпоинту (например `/cdek/calculate/`) с ДВУМЯ разными
   подсунутыми XFF → сравнить поведение бакетов. Зафиксируй результат в PR: бакеты раздельные
   или общие — от этого зависит формулировка вывода, но не объём работ.
2. **Закрутка доверия**: env `FORWARDED_ALLOW_IPS` (чтение в entrypoint или конфиге),
   дефолт `*` для локалки; в helm values для test — реальный CIDR/IP ingress-контроллера.
   Спуфинг XFF снаружи после этого должен игнорироваться (ключ = адрес, который прислал ingress).
3. **Лимит на гостевой эндпоинт** `GET /orders/guest/{order_id}/` — `@conditional_limit("10/minute")`
   (как соседние чувствительные чтения).
4. **Тесты (pytest)**: разные XFF → разные бакеты; запрос без доверенной цепочки → ключ не из
   подсунутого XFF; гостевой эндпоинт после N запросов → 429. Учти `conditional_limit`: в тестах
   ENVIRONMENT не production — либо тестируй через monkeypatch env + отдельный Limiter,
   либо покрой логику ключа/конфигурации unit-тестами, а 429 — интеграционно на test (п.1).
   Не ломай существующий suite (691+ тест).
5. **Комментарии**: `onec.py:66-69` и любые другие места, описывающие «лимит по IP пода», —
   привести к новому поведению.
6. **Мутация-доказательство в PR**: вывод живого прогона на test — до фикса спуфинг XFF даёт
   свежий бакет (или лимит общий), после — 429/игнор спуфинга.
