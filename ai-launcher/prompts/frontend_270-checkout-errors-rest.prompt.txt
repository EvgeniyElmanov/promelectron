## Задача

Остаток обработки ошибок создания заказа после #211/#269. Ядро уже в main (PR #282):
`frontend/src/composables/useOrderSubmission.js` + `frontend/src/components/OrderDeliveryNotice.vue`
на 409 пересчитывают тариф через `POST /cdek/calculate/`, показывают старую/новую цену и
требуют подтверждения; на 503 — «недоступен» + кнопка «Повторить». Остаток — три куска,
решения по всем СОГЛАСОВАНЫ с владельцем (2026-10-06, зафиксированы в теле issue):

1. **422 → читаемый тост.** Сервер шлёт `detail` массивом объектов Pydantic
   (`[{loc, msg, type}, ...]`) — в тост уходит `[object Object]`. Нужен форматтер:
   собрать читаемый русский текст (loc → человеческое имя поля, msg → текст).
2. **503 → один авто-retry.** Один автоматический повтор создания заказа с задержкой ~2–3 сек,
   дальше — текущее поведение («недоступен» + кнопка «Повторить»). Безопасно: при 503 заказ
   не создаётся (fail-closed на сервере), дубля не будет.
3. **409 → авто-retry при неизменной цене.** Если пересчёт вернул ТУ ЖЕ цену, что видел
   пользователь — создавать заказ сразу, без плашки и клика. Если цена изменилась — поведение
   #269 (плашка со старой/новой ценой + подтверждение) НЕ меняется. Сравнение цен — с учётом
   копеек/округления (точное совпадение по копейкам; никаких «почти равно» — это деньги).

## Порядок

1. Форматтер ошибок 422 (хелпер, например рядом с `useOrderSubmission` или в utils):
   массив Pydantic → читаемый текст; одиночная строка `detail` — как сейчас.
   Подключить в ветку «прочие статусы» обработчика.
2. Ветка 503: один авто-retry (setTimeout ~2.5 сек) с понятным состоянием («повторяем…»),
   при повторном 503 — текущая плашка/кнопка «Повторить».
3. Ветка 409: после успешного пересчёта сравнить новую цену с той, что видел пользователь;
   совпала → немедленный повтор создания заказа (тот же submit) + уведомление об успехе;
   отличается → текущая плашка подтверждения.
4. Тесты vitest: 422 → читаемый текст (массив detail), 503 → авто-retry вызван один раз,
   повторный 503 → кнопка; 409 с той же ценой → заказ создан без notice, 409 с новой ценой →
   notice как в #269. Прогнать полный `make test-frontend`.
5. После мержа PR: убедиться, что e2e `checkout.spec.js` зелёный (CI post-deploy).
