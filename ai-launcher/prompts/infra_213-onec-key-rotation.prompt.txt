## ⚠️ Главное: ротация, а не перенос

Значение уже в git и во всей истории репозитория. Перенос его в SOPS **ничего не чинит** —
старый ключ остаётся скомпрометированным. Порядок именно такой:

1. **Сначала** новые ключи: разные для test и prod.
2. Заведи их в SOPS / GitHub Secrets, из `secret.yml` убери.
3. Выкати и убедись, что 1С-интейк работает с новым ключом.
4. **Только после этого** старый ключ можно считать выведенным.

⚠️ Смена ключа ломает интеграцию с 1С на стороне 1С. Прежде чем катить в prod — **остановись и
спроси владельца**: кто и когда меняет ключ в 1С. Выкатить новый ключ, не согласовав, значит
уронить обмен каталогом.
