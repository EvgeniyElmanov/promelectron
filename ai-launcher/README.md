# `ai-launcher/` — пульт запуска задач

Здесь лежит то, с чего начинается рабочая сессия: **борд** (`BOARD.md`) — что можно взять
прямо сейчас, и **промпты** (`prompts/`) — с чем именно запускается агент по каждому пункту.

Репу ведут двумя агентами: один разработчик на **Claude Code**, другой на **Kimi Code**.
Борд у них **один на двоих**, поэтому кнопка на нём написана нейтрально — через `make ai`,
а чем эта цель запускается, решается машинно-локально.

```
ai-launcher/
├── BOARD.md        # пульт: что брать, что занято, что ждёт условия
├── CONVENTIONS.md  # форма борда, замки, порядок сверки — общее для claude и kimi
└── prompts/        # <зона>_<issue#>-<слаг>.prompt.txt — тело задачи для запуска
```

---

## Как запустить пункт

Скопируй кнопку из `BOARD.md` и выполни **из корня репозитория**:

```bash
make ai PROMPT=ai-launcher/prompts/e2e_186-cart-select-flaky.prompt.txt
```

`make ai` читает файл промпта и передаёт его текст твоему агенту. Проверить, что лончер
настроен на этой машине:

```bash
make ai-check
```

## Настройка на своей машине: `Makefile.override.mk`

Файл лежит в корне репозитория, **в `.gitignore`** и подключается из `Makefile` через
`-include`. На машине, где его нет, всё остальное в `Makefile` обязано работать как раньше —
ломается только `make ai`, и он честно об этом говорит.

Заводится один раз, руками. Задаёт три переменные:

| Переменная | Что значит |
|---|---|
| `AI_CMD` | сама команда агента со всеми флагами |
| `AI_PROMPT_OPT` | как этой команде передаётся промпт: пусто — позиционным аргументом, `-p` — флагом |
| `AI_NAME_OPT` | флаг имени сессии, если у CLI такой есть; не задан — `NAME=` игнорируется |

### Claude Code

```make
AI_CMD        := claude --dangerously-skip-permissions --model opus
AI_PROMPT_OPT :=
```

`claude` берёт промпт последним позиционным аргументом, поэтому `AI_PROMPT_OPT` пуст.

### Kimi Code

```make
AI_CMD        := kimi --yolo
AI_PROMPT_OPT := -p
```

`kimi` берёт промпт флагом `-p` и остаётся интерактивным (`--print` — отдельный режим,
для лончера он не нужен).

### Что ещё уместно держать в этом файле

Всё, что завязано на окружение конкретного разработчика и потому не может лежать в репозитории:
пути к его хранилищу секретов, локальные каталоги, свои алиасы запуска. Например, вход в проект
без промпта:

```make
.PHONY: claude
claude:
	@exec claude --dangerously-skip-permissions $(ARGS)
```

Секреты для MCP-серверов подтягивай здесь же, на запуске (`pass`, `1password` и т.п.), а не
храни в переменных окружения оболочки. Присваивай **отдельной строкой**, а не префиксом
команды: под `set -e` падение в префиксе (`VAR=$(...) cmd`) проглатывается, и агент стартует
с пустым секретом.

## Промпты

Имя файла: `<замок>_<issue#>-<короткий-слаг>.prompt.txt` — по имени видно, какая зона
блокируется и о каком issue речь. Пункт на нескольких замках берёт основной замок либо
`fullstack`, а полный список замков указывается в самом промпте и на борде.

Промпт — это **вход в работу, а не сама работа**. Он задаёт: где работать (обязательно
отдельный worktree), какой issue берётся, что уже известно, где границы и по какому
проверяемому критерию пункт считается закрытым. Разборы и история сюда не пишутся — им
место в issue, `.agent/DECISIONS.md` и `git log`.

Кнопка на борде появляется **только у пункта, для которого написан промпт**. Нет промпта —
пункт живёт в разделе «заведено, но кнопки нет»: иначе агент стартует с чистого листа и
придумает задачу сам.

## Что тут источник истины

**Бэклог — это GitHub Issues** на `AutonomaCo/promelectron` плюс доска GitHub Project.
`BOARD.md` — его **витрина**, а не второй список. Расхождение между ними — всегда ошибка
борда, а не бэклога.

Правила формы борда, замков и сверки — в [`CONVENTIONS.md`](./CONVENTIONS.md).
Команды: `/board`, `/board refresh`, `/sessions` (Claude) · `/skill:board`, `/skill:sessions` (Kimi).
