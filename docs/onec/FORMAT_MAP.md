## 1. Сущность 1С → таблица Promelectron

| Сущность 1С (OData) | Назначение | Таблица/модель Promelectron |
|---|---|---|
| `Catalog_Номенклатура` | Товары и группы (папки) | `products` (`Product`), папки не загружаются |
| `Catalog_КатегорииНоменклатуры` | Категории каталога | `categories` (`Category`) |
| `ChartOfCharacteristicTypes_ДополнительныеРеквизитыИСведения` | Определения характеристик | `products.attributes` JSONB (ключи), см. раздел 3 |
| `Catalog_Номенклатура_ДополнительныеРеквизиты` | Значения характеристик товара | `products.attributes` JSONB (значения) |
| `Catalog_ЗначенияСвойствОбъектов` | Справочник enum-значений характеристик | `products.attributes` JSONB (разрешённые значения) |
| `InformationRegister_ЦеныНоменклатуры` | Цены по видам цен | `products.price` (выбранный вид цен, раздел 4) |
| `AccumulationRegister_ЗапасыНаСкладах_Balance` | Остатки по складам | `products.stock` (сумма, кламп ≥ 0) |
| `Catalog_КлассификаторЕдиницИзмерения` | Единицы измерения | справочно; нормализация единиц характеристик |
| `Catalog_ВидыЦен` | Виды цен | справочно; выбор вида цен → `products.price` |
| `Catalog_НоменклатураПрисоединенныеФайлы` | Файлы/изображения | `products.images` (Фаза изображений, out of scope) |
| `Catalog_ПрайсЛисты_Номенклатура` | Прайс-листы | не используется (в сэмплах пусто) |
| `AccumulationRegister_ЗапасыНаСкладах` | Движения (не Balance) | не загружается, только справочно |

Сырые payload до применения маппинга складываются в `onec_change_log`
(`OnecChangeLog`, intake Фазы 1, PR #125).

## 3. Справочник характеристик (по фактуре отчёта)

Целевая схема — `products.attributes` JSONB (gap зафиксирован в
`.agent/runs/catalog-meilisearch-filters-1c-0720/research/codebase-integration.md`;
EAV не вводим). Формат значения: `{name, value, value_number?, value_unit?}`.

Классификация типов по `ValueType.Types[0]` определения:

| `ValueType.Types[0]` | Тип | Хранение |
|---|---|---|
| `CatalogRef.ЗначенияСвойствОбъектов` | enum | `value` = `Description` из `Catalog_ЗначенияСвойствОбъектов` по GUID |
| `Number` | number | `value_number` |
| `String` | string | `value` |
| `Boolean` | bool | `value` |

Найденные в сэмплах определения (`attributes_def.json`, 5 шт.):
`mF` (enum), `V` (enum), `Без канифоли`, `Бренд` (enum), одно без имени.
Большинство назначений в `product_attributes.json` ссылаются на определения
вне сэмпла (битые GUID — артефакт обрезанной выгрузки, не данных).

**Кандидаты в числовые** (regex `число + единица`, доля ≥ 50 %):

| Свойство (Owner GUID) | Единица | Примеры |
|---|---|---|
| `d62aec37-7c07-11eb-80d5-00155d006601` (сечение) | мм² | «10,0мм2» → 10.0; «16,0мм2» → 16.0 |
| `facc9c07-8874-11eb-80c9-d45d647f1831` (фасовка) | шт | «1шт» → 1; «2шт» → 2 |

Для numeric-кандидатов загрузчик Фазы 4 заполняет `value_number` +
`value_unit` (нормализация `мм2` → `мм²` по таблице `KNOWN_UNITS`
анализатора) — это вход фасетных фильтров Meilisearch.
Значения без буквенной единицы («2016/2025/2032») кандидатами не считаются.

## 4. Виды цен → `products.price`

Найденные виды цен (`price_types.json`, все `DeletionMark = false`):

| GUID | Название |
|---|---|
| `143c81a9-1094-11f0-8170-00155d0a290e` | БазаСВ |
| `86e087df-620a-11eb-948d-d45d64d20ea1` | Копт |
| `616479e8-7dd8-11ed-9d18-94de80b28a88` | МинМП |
| `261c5bb1-1096-11f0-8170-00155d0a290e` | ОзонСВминимальные |
| (5-й вид) | ОзонСВосновная |

**Решение:** в `products.price` загружается **один** выбранный вид цен —
розничный базовый. В сэмплах `prices_try.json` используется вид цен
`3d3bea35-5d6a-11eb-948a-f81a67046005` (отсутствует в обрезанном
`price_types.json` — битая ссылка сэмпла). Конкретный GUID вида цен —
конфигурация загрузчика Фазы 4 (env var, не хардкод), уточняется на живой
выгрузке MinIO (пункт 5 чек-листа). Маркетплейс-виды (`ОзонСВ*`) в
`products.price` не идут.

## 5. Правило «активные» записи (D-08/D-09)

- Нулевой GUID `00000000-0000-0000-0000-000000000000` = NULL во всех
  перекрёстных ссылках (не битая ссылка).
- Общее: `DeletionMark = false`.
- Номенклатура: дополнительно `ТипНоменклатуры = "Запас"` и
  `IsFolder = false` (услуги/папки не загружаются; в сэмплах из 11 записей
  `Catalog_Номенклатура` активна 1 — остальные папки/услуга «Доставка»).
- Цены: `Актуальность = true` + выбранный вид цен (раздел 4).
- Остатки: сумма `КоличествоBalance` по складам, результат < 0 → 0 (B-02).

## 6. Замечания по CommerceML-диалекту мока (Фаза 7, #124)

Мок `mocks/onec-server` (worktree `onec-mock-server-0730`) генерирует
CommerceML 2.x, два документа:

- `import.xml` — `КоммерческаяИнформация/Каталог/Товары/Товар`
  (`Ид` = onec_id, `Артикул` = sku, `Наименование` = name,
  `Группы/Ид` = категория, `ЗначенияСвойств/ЗначенияСвойства` —
  характеристики по `Ид` свойства) + `Классификатор/Группы` (категории)
  и `Классификатор/Свойства` (определения характеристик).
- `offers.xml` — `ПакетПредложений/Предложения/Предложение`
  (`Ид`, `Артикул`, `Наименование`, цены, количество).

Анализатор определяет роль по корню: `Каталог` → import,
`ПакетПредложений` → offers. Отличия от OData-формата: идентификаторы —
те же GUID 1С, характеристики inline (без джойна справочников), единый
вид цен в предложении. Маппинг на таблицы — тот же (разделы 1–5),
источник полей — XML-теги вместо OData-полей.
