# Журнал сессий

`session-log.md` — что делалось в каждой сессии, с доказательствами; `session-log-archive.md` —
то же, старое (3563 строки).

## Читать с оговоркой

Журнал полезен, когда надо восстановить «как мы сюда пришли», и вреден, когда его читают как
инструкцию. Он **append-only, устаревает с первого дня и не является источником истины ни по
одному вопросу**:

| Вопрос | Где правда |
|---|---|
| что делать дальше | открытые GitHub Issues + `ai-launcher/BOARD.md` |
| почему у нас так устроено | `docs/decisions/` |
| как устроен проект сейчас | `PROJECT_CONTEXT.md`, код |
| что заблокировано | `docs/blockers.md` + раздел «⏰ Ждут условия» на пульте |

## Почему он не в контексте агента

Ни один агент не грузит этот каталог автоматически, и это осознанно. Исследование ETH Zurich
«Evaluating AGENTS.md» (arXiv 2602.11988) на 138 задачах и четырёх агентах показало, что
контекстные файлы не повышают долю успешных решений, а стоимость инференса поднимают более чем
на 20%. Тот же аргумент у Keep a Changelog про генерацию из git-лога: «commit log diffs as
changelogs is a bad idea: they're full of noise».

Поэтому: сюда пишут, отсюда читают **по запросу**, а долговременное знание дистиллируется в
`docs/decisions/`.

## Как писать запись

Дата, кто работал, что сделано — **с доказательствами**: номер PR, SHA, вывод прогона.
Формулировка «починил корзину» через месяц не значит ничего; «`Cart.vue:431` — вотч на
`selectionSignature`, PR #178, merge `1569056`, 371/371 vitest» значит.

Когда `session-log.md` перерастает разумный размер — верхняя часть уезжает в архив, а не
удаляется.
