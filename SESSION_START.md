# SESSION_START — Шаблон входа в сессию Kimi CLI

> **Никаких bash-команд. Всё работает через текст в чате.**

---

## Рекомендуемый способ: Диспетчер (автопереключение ролей)

### 1. Начало сессии (один раз)

Вставь в чат Kimi CLI:

```
Прочитай .agent/DISPATCHER_PROMPT.md и следуй этим инструкциям строго.
```

Или полный вариант с первой задачей:

```
Прочитай .agent/DISPATCHER_PROMPT.md и следуй этим инструкциям строго.

Задача: <ВСТАВЬ ЗДЕСЬ ПЕРВУЮ ЗАДАЧУ>
```

### 2. Все следующие задачи

Просто пиши:

```
Задача: <ОПИСАНИЕ ЗАДАЧИ>
```

Диспетчер автоматически:
- Сбросит предыдущую роль
- Определит новую роль по ключевым словам
- Прочитает нужного агента
- Выполнит задачу

---

## Альтернатива: Фиксированная роль (если весь день работаешь над одним направлением)

Если целый день только backend (или только frontend) — не нужен диспетчер:

```
Проект Promelectron. Роль: backend-dev. Задача: <ВСТАВЬ ЗАДАЧУ>

Прочитай PROJECT_CONTEXT.md, BACKLOG.md, BLOCKERS.md, SESSION_LOG.md.
Прочитай .kimi/agents/backend-dev.md и .kimi/rules/pre-edit-checklist.md.
После работы обнови SESSION_LOG.md.
```

Потом просто:
```
Задача: <СЛЕДУЮЩАЯ ЗАДАЧА>
```

> ⚠️ **Важно:** В фиксированной роли смена на другую роль работает плохо.
> Если понадобилось переключиться — используй диспетчера (`.agent/DISPATCHER_PROMPT.md`).

---

## Вариант: Сквозная фича (несколько ролей в одной задаче)

> Для задач вроде YooKassa E2E → CI/CD → backend → Helm, где одна фича требует работы нескольких ролей.

```
Проект Promelectron. Задача: <YK-XXX: Название фичи>

Будет затронуто: e2e-tester + backend-dev + devops (или перечисли нужные роли).
Работай гибко — читай .kimi/agents/<ROLE>.md перед каждым значимым блоком.
Перед правкой кода — .kimi/rules/pre-edit-checklist.md.
После работы обнови SESSION_LOG.md.
```

**Как это работает:**
- Ты не переключаешь роль формально
- Агент сам понимает, когда ему нужно думать как e2e-tester, а когда как devops
- Не нужно вставлять диспетчера

**Когда использовать:**
- Одна фича проходит через backend → frontend → devops
- E2E тест → CI/CD pipeline → Helm деплой
- Любая задача, где роли работают над ОДНИМ потоком

**Когда НЕ использовать:**
- Независимые задачи разных ролей (здесь лучше диспетчер)
- Когда нужна строгая специализация

## Как работает переключение (пример)

```
Ты: Прочитай .agent/DISPATCHER_PROMPT.md и следуй инструкциям
Kimi: 🔄 Диспетчер активирован. Готов к работе.

Ты: Задача: Создай API для промокодов
Kimi: 🔄 Сброс роли...
      🎯 Роль: backend-dev
      [читает backend-dev.md]
      [выполняет задачу]
      ✅ Готово. Роль: backend-dev.

Ты: Задача: Сделай страницу для применения промокода
Kimi: 🔄 Сброс роли...
      🎯 Роль: frontend-dev
      [читает frontend-dev.md]
      [выполняет задачу]
      ✅ Готово. Роль: frontend-dev.

Ты: Задача: Настрой CI/CD
Kimi: 🔄 Сброс роли...
      🎯 Роль: devops
      [читает devops.md]
      [выполняет задачу]
      ✅ Готово. Роль: devops.
```

---

## Если диспетчер "залип" (не сменил роль)

Редко, но бывает в очень длинных сессиях. Решения:

1. **Повтори команду сброса:**
   ```
   Сбрось роль. Прочитай заново .agent/DISPATCHER_PROMPT.md.
   Задача: <...>
   ```

2. **Или начни новую сессию Kimi CLI**

3. **Или укажи роль явно (100% надёжно):**
   ```
   Роль: frontend-dev. Задача: Сделай страницу checkout
   ```

## Роли и типичные задачи

| Роль | Ключевые слова | Типичная задача |
|------|---------------|-----------------|
| `backend-dev` | API, модель, миграция, сервис, endpoint, webhook, JWT, заказ, корзина (API) | API, модели, миграции, сервисы |
| `frontend-dev` | Vue, компонент, страница, форма, Pinia, UI, CSS, router, корзина (UI) | Компоненты, composables, Pinia |
| `devops` | Docker, Helm, K8s, CI/CD, деплой, nginx, secret, config | Helm, Docker, CI/CD, мониторинг |
| `e2e-tester` | E2E, Playwright, тест сценарий, browser, click | Playwright тесты |
| `code-reviewer` | review, ревью, проверь код, findings, quality | Ревью кода |
| `security-reviewer` | security, аудит, уязвимость, SQL injection | Security audit |
| `project-manager` | план, спринт, приоритет, бэклог, оценка | Планирование, приоритеты |
| `dispatcher` | — | Автопереключение ролей |

## Полезные файлы (читай при необходимости)

| Файл | Когда читать |
|------|-------------|
| `.kimi/rules/pre-edit-checklist.md` | Перед правкой кода — тесты, миграции, env |
